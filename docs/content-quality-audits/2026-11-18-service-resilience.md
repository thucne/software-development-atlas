## Primary-source checks and changes

1. **Safe degradation vs required failure.** The original call-flow diagram routed both `OPEN` breaker and exhausted retry budget through a generic fallback to a "useful response", suggesting that a critical operation might succeed. Now the diagram has separate conditional branches: approved optional fallback or explicit error for required work. The `HALF_OPEN` probe state is handled separately in the state machine. See [Microsoft Circuit Breaker pattern](https://learn.microsoft.com/en-us/azure/architecture/patterns/circuit-breaker): failures can return exceptions or *meaningful* fallbacks; recovery probes must be bounded.
2. **Retry-budget scope.** The prior TL;DR used "strict global retry budgets" without showing how a global counter was enforced. The revised lessons explain a local per-process/client budget versus a coordinated fleet-wide limit. The example 1,000 normal / 100 retry calls per minute is now explicitly constructed, not a prescribed default. [Microsoft transient-fault handling](https://learn.microsoft.com/en-us/azure/architecture/best-practices/transient-faults) recommends aggregate budgets in addition to per-request attempt caps; [AWS Builders' Library](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/) explains retry amplification and local token-bucket mitigation.
3. **Bulkhead and overload.** Verified the distinction between arrival-rate limits and concurrency limits, and that capacity isolation has real efficiency/operational costs. The optional recommendation vs critical checkout example is a conditional architectural sketch rather than a universal guarantee. Source: [Microsoft Bulkhead pattern](https://learn.microsoft.com/en-us/azure/architecture/patterns/bulkhead).
4. **Incident provenance and natural language.** The e-commerce example's 80 ms to 8 s degradation is explicitly labeled a constructed hypothetical scenario in each language at the start of section 11, rather than being presented as a documented production outage. The unsupported API Gateway-specific pool assertion in the TL;DR was replaced with a topology-neutral shared outbound-capacity risk. Replaced alarmist translated language and confirmed the same consequences/causes/corrective action in EN and VI.
5. **Deadline, partial failure, business truth.** The 2-second arithmetic fits the stated budget and is marked illustrative. Request cancellation is qualified by runtime/protocol; retries remain subject to effect-boundary idempotency; optional cache fallbacks are not conflated with payment or authorization success. Readiness distinguishes an optional degraded dependency from inability to serve critical traffic. Sources above plus cross-links to the Atlas Timeouts, Retries, Idempotency, Partial Failure, and Caching lessons.
6. **Usability and references.** Both reference lists now contain direct primary links. Verified the same policy sheet, self-check answer, glossary elements, sources, and internal EN/VI paths. The sequence diagram is conceptual, not executable implementation code; no provider-specific default configuration is asserted.
